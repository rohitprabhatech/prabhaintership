## Recording Rules

- Use only an approved development/isolated QA environment. Use the synthetic values in [08-manual-testing-guide.md](./08-manual-testing-guide.md), checking for collisions first.
- The actual-result field must describe observed behavior, not repeat the expected result. Record environment/date and sanitized evidence. Never attach passwords, hashes, bearer tokens, or real personal/financial data.
- For a confirmed defect, enter a unique bug ID and severity/priority. Leave them `—` until a reproducible defect is established. For unavailable functionality, keep status `Not Run` and note it as a limitation rather than marking a nonexistent feature as failed.
- Do not execute destructive operations against existing data. Every test that writes a record must use synthetic test data in a non-production schema.
